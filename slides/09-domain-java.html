Real-World Case Study

Domain Example 1: Java & Spring Boot

Scenario: Adding input validation & clean error handling to a User API endpoint.

❌ Low-ROI Brute Force Prompt Tokens: ~140k (Scans repo)

"My user signup endpoint is crashing with 500 errors when users enter bad emails. Here is my @workspace. Please fix the validation and error handling."

Why this fails:
  • Agent scans 35 entity & service files looking for "signup".
  • Generates messy manual if (email == null) checks inside the controller method.
  • Burns 140,000 tokens and wastes 30+ seconds.
✅ Value-Maxed Precision Prompt Tokens: ~2.1k | Latency: 1.2s 
Context: `@UserController.java:L25-45` and `@SignupRequest.java`

Task:
1. Add `@Valid` with `@Email` and `@NotBlank` annotations to `SignupRequest`.
2. In `@GlobalExceptionHandler.java`, add `@ExceptionHandler(MethodArgumentNotValidException.class)` to return HTTP 400 with field errors.

Constraints:
- Do not modify database entities or controller signatures.
- Follow standard Spring Boot `@RestControllerAdvice` pattern.
Why this wins:
  • Pins the exact 2 files; model outputs clean Spring code in 1 pass.
  • 98% fewer tokens, instantaneous response under 1.5s!

🎙️ Speaker Talking Points (4 mins):

  • Contrast the Two Prompts: Notice how the bad prompt relies on `@workspace` and vague instructions. The model has to guess your validation philosophy and scans dozens of unrelated files.
  • The Precision Fix: By referencing only `@UserController.java:L25-45` and `@SignupRequest.java`, you feed the model pure signal. It uses standard Spring `@Valid` and `@RestControllerAdvice` without touching your database layer.
  • Takeaway: Always specify the exact files and state the architectural pattern you want (e.g. `@RestControllerAdvice`).
